## Production-check gap (for humans to settle; nothing amended here)

Two voice registries exist for one academy, and no check relates them:

| Registry | Read by | Serves | This academy |
|---|---|---|---|
| `academy.yaml brand.voices` | runtime `server/guide-voice.ts` | on-demand TTS (audio stories, read-along `speak()`, Guide replies) | present (`en` Alice) |
| `course-production/<course>/narration-voices.json` | foundry `tools/narration/beats.mjs` | prerecorded read-along / conversation beats | absent — and unused by design |

Suggested amendments (owner: foundry; drafted here only):

1. **Contract** (`docs/narration.md`): add a line to the voice-registry section defining the
   on-demand-only posture — "a course whose audio blocks all narrate via `audioScript` with no
   `presentation: readalong/conversation` needs no course-production narration-voices.json; its production
   voice registry is `academy.yaml brand.voices`. A beats dry-run exit 2 (no registry) on such a course is
   expected, not a gap."
2. **Check** (foundry `tools/qa/` + `perceptor check`): a narration-posture audit that classifies the package
   (any `readalong`/`conversation` block?) and then asserts exactly one of:
   (a) readalong/conversation present → `narration-voices.json` exists, every package locale resolves to a
   gemini-tts entry, and the manifests register every beat — OR (b) on-demand-only → `brand.voices` covers every
   package locale (and, worth asserting: every `audioScript` ≤ 1,200 chars, the server synthesis clip limit).
   This turns today's exit 2 into a pass/fail with a reason.
3. **Ledger** (`docs/improvement-ledger.md`): a row for the nightly-sweep template line "Narration: embedded in
   audio blocks — nothing to produce", which reads as a production verdict but never consults the beats tool;
   the sweep should either run the new posture audit or label the line "content unchanged; production posture
   unaudited".
